## 技术栈

Python 3.12 / Flask 提供管理 API、会话登录与订阅输出，SQLite 保存配置和账号，Pillow 处理台标。前端为原生 HTML / CSS / JavaScript，无需 Node 构建；生产镜像使用 Gunicorn，并以非 root 用户运行。

## 不使用 Docker 的本地运行

安装 Python 3.12 和 Git，克隆自己的 fork 或项目仓库后，进入项目根目录。

### macOS / Linux

```sh
git clone https://github.com/cachemiao/m3u-studio.git
cd m3u-studio
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
DATA_DIR="$PWD/data-dev" .venv/bin/python -m flask --app app/server.py run --host 127.0.0.1 --port 8324 --debug
```

### Windows PowerShell

```powershell
git clone https://github.com/cachemiao/m3u-studio.git
cd m3u-studio
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
$env:DATA_DIR = "$PWD\data-dev"
.\.venv\Scripts\python.exe -m flask --app app/server.py run --host 127.0.0.1 --port 8324 --debug
```

打开 `http://127.0.0.1:8324`，首次在网页创建账号。开发数据保存在独立的 `data-dev/`，不会使用 Docker 的数据卷。端口冲突时修改 `--port`；按 Ctrl+C 停止，修改文件后开发服务器自动重载。

这里绑定 `127.0.0.1`，仅供本机开发；不要将 Flask 调试服务器用于公网或生产部署。新安装不需要 `.env`，也没有默认管理密码。

## 验证修改

在虚拟环境中安装 pytest，并运行相关测试；提交前检查修改涉及的功能。以下以 macOS / Linux 为例，Windows 将 `.venv/bin/python` 换成 `.\.venv\Scripts\python.exe`。

```sh
.venv/bin/python -m pip install pytest
.venv/bin/python -m pytest tests -q
```

Node.js 18+ 用于前端逻辑测试，不是应用的构建或运行依赖：

```sh
node --test tests/test_channel_drag.cjs tests/test_editor_core.cjs tests/test_i18n.cjs tests/test_import.cjs tests/test_logo_upload.cjs tests/test_source_check.cjs
```

界面改动请同时检查中英文、深浅模式和手机宽度；部署配置改动先执行 `docker compose -f docker-compose.image.yml config --quiet`。更多验证记录见 [VALIDATION.md](../VALIDATION.md)。

## 提交 Pull Request

1. Fork 仓库，从最新 `main` 创建自己的分支；本地开发时将克隆地址改为自己的 fork。
2. 每个 PR 解决一个明确问题，保持改动范围集中；涉及行为变化时补充对应验证。
3. PR 描述说明问题、最终行为和验证结果；界面改动附截图，用户可见变化同步文档。
4. 提交前用 `git diff --check` 和 `git status` 检查内容，不提交 `data/`、`data-dev/`、`.venv/`、`.env`、账号、私人播放地址或无权分发的台标。
