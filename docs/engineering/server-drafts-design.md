# 服务端草稿设计（待评审，尚未实现）

目标是跨设备继续编辑，不是为了改变“自托管”的定义。当前版本继续使用浏览器草稿，前端拆分不改变保存位置。

## 状态与所有权

- 已发布配置、服务器草稿和浏览器恢复副本必须分开；保存草稿不生成或改变正式订阅。
- 草稿按稳定账号 ID 隔离，不能按可变用户名关联。修改账号名称不应丢失草稿，账号删除/重建必须有清楚的清理规则。
- 浏览器副本用于断网和异常关闭恢复；需要记录所属账号、基于的发布 revision、服务器草稿 revision 及保存时间，不携带口令或会话密钥。

## 冲突协议

建议独立 GET /api/draft 和带前置版本条件的 PUT /api/draft。首次读取不存在的草稿应明确返回不存在，而不是悄悄复制已发布内容。草稿写入必须检查草稿版本和它基于的发布版本，过期写入返回 409，不做最后写入覆盖。

两个标签页或设备发生分歧时，展示服务端与本地副本的时间、版本和变更概览，由用户选择保留/恢复；第一版不自动合并频道排序或字段冲突。设备断网恢复后先同步版本，不能直接重放旧修改覆盖更新内容。

发布必须原子校验发布 revision、保存发布前历史并更新正式配置；只有与本次发布一致的草稿才能标记为已发布/清理。另一设备发布后，旧草稿必须提示基线变化。

## 迁移、权限与隐私

新增草稿表之前，先增加结构迁移与恢复样例。第一次接入时明确提示是否导入浏览器草稿，不能默默上传既有浏览器内容。保留放弃上传和导出恢复副本的选项。

草稿接口沿用登录和跨站请求保护，限制体积与写入频率；不在日志中记录私人播放地址。完整备份覆盖草稿，JSON 备份是否包含草稿需明确定义。静态演示继续只使用内存适配器，不能接入服务器草稿。

## 必须通过的验收

同账号跨设备继续编辑；账号隔离；两个标签页冲突；断网重连；发布与自动保存同时发生；账号改名；旧浏览器草稿的显式迁移；结构升级/失败恢复；草稿丢失或不可用时正式订阅不受影响。

本文件只定义下一阶段的决策与验收条件，尚未创建 API、表或自动上传行为。
