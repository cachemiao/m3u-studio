# 前端模块边界

正式版与静态演示版共享相同的应用代码，不使用框架或 Node 构建步骤。

- `app.js`：初始化依赖、主列表渲染、状态变更入口与选择控制。
- `workspace-model.js`：每个工作区独立的可变状态、选择集合、编辑上下文和运行状态。正式内容、草稿和已发布基线仍按原语义区分。
- `transport.js`：HTTP 请求、会话失效与结构化 API 错误；不操作页面状态。
- `controllers/`：拖动、编辑、导入、批量编辑、台标、剪贴板、订阅/历史、会话、源检测、提示。控制器通过传入的上下文和工作区模型协作，不读取旧的裸全局状态变量。
- 控制器先创建，再统一注册公开方法，最后执行 `install()` 绑定事件，避免初始化顺序影响功能。
- 浏览器存储接口通过 `createDraftStore` 注入；正式版保留原浏览器草稿，演示版返回空存储。
- 演示版注入内存 API、模拟检测及内置台标允许策略。构建只复制共享模块与生成示例数据，不再截取/修改应用 JS 函数。
- `studio.css` 保留有序导入；`styles/` 按原有级联顺序分层，内嵌图标通过变量共享。本轮没有重排跨组件覆盖或改变布局。

回归基线：`npm test`、`npm run test:browser`。测试不再从 app.js 截取导入、上传或拖动函数。浏览器测试使用独立临时数据库和测试账号，不能读取部署数据。

Node 和 Playwright 只用于开发测试，不是应用运行或 Docker 镜像的新增依赖。
