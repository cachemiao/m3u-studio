# 本轮工程改进与验证

本轮按 CI/行为基线、前端职责拆分、服务端访问策略、数据库结构版本的顺序提交。服务端草稿仅形成设计，不改变现有浏览器草稿保存方式。

## 已完成

- `Application checks` 在 main、engineering 分支推送、Pull Request 和手动触发时执行。覆盖 Python、JavaScript、真实浏览器及静态演示资源一致性检查；不需要发布凭据。
- 应用状态、HTTP 通信与十个功能控制器分离。演示版通过显式适配器复用正式代码，不再截取并替换应用函数。样式保持原有级联顺序分层，重复内嵌图标共享变量。
- 远程导入与源检测分别配置访问范围；验证 DNS 全部结果，连接固定到已验证地址，每次重定向重新验证。公网及家庭内网默认可用；严格白名单仅为可选高级配置，详情见[访问策略](network-access.md)。
- SQLite 引入结构版本 1，在事务中识别并升级现有无版本数据库；拒绝未知未来结构。验证旧数据保留、重复启动、失败回滚、备份恢复及恢复后的账号/订阅/台标。
- [服务端草稿设计](server-drafts-design.md)独立记录账号隔离、版本冲突、离线与现有本地草稿迁移选择；没有新增草稿 API 或数据库表。

## 验证结果

本地集成验证：122 项 Python 测试、70 项 JavaScript 测试、5 项浏览器流程全部通过；两份 Compose 配置校验通过；演示版重新构建后与已提交资源一致。

浏览器流程覆盖编辑/撤销/重做、本地草稿刷新恢复且未发布、多选频道整体拖动及撤销、非安全上下文复制回退、演示版重置及无后端/外部请求，并检查三种视口宽度。

在同一 Chromium、相同演示数据和视口下，拆分前后的深色/浅色截图逐像素比较均无差异。这是固定场景的布局回归证据，不代表覆盖所有浏览器和所有交互。

## 明确的边界

- 工作流运行与“合并必须检查通过”是两件事。仓库应在分支保护或规则集中将 `Application checks / checks` 设为必需检查；本轮没有修改仓库管理规则。
- CSS 本轮保留覆盖顺序，尚未进行跨组件选择器合并或整体重新设计。
- 访问策略有针对性回归测试，不等同于完整安全审计；网络部署仍需可信入口。环境代理不用于用户指定的导入/检测 URL。
- 结构版本是现有 v0.6.x 数据库的基线，不承诺将未来数据库直接交给旧镜像使用。跨结构版本回退应恢复兼容备份，见[迁移与恢复](database-migrations.md)。
- Node 和 Playwright 仅为开发依赖，应用运行无需 Node 构建。
