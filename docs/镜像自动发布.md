# GitHub Release → Docker Hub / GHCR

工作流位于 `.github/workflows/docker-publish.yml`。发布正式 GitHub Release 后，自动检出该 Release 对应的标签，运行 Python 和 Node 测试，再构建 AMD64 / ARM64 镜像并推送到 `cachemiao/m3u-studio` 和 `ghcr.io/cachemiao/m3u-studio`。

例如发布 `v0.3.5`，将生成 `cachemiao/m3u-studio:0.3.5` 和 `cachemiao/m3u-studio:latest`，GHCR 同步生成相同版本与 `latest` 标签。草稿、预发布版和普通代码提交不会触发镜像发布。标签须采用 `v主版本.次版本.修订版本` 或不带 v 的同类格式。

## 一次性配置

1. 在 Docker Hub 的 Account settings → Personal access tokens 创建用于 GitHub Actions 的访问令牌，赋予 Read & Write 权限，不需要 Delete 权限。
2. 在 GitHub 仓库 Settings → Secrets and variables → Actions → New repository secret 添加 `DOCKERHUB_TOKEN`，值为上述令牌。
3. 令牌仅保存在 GitHub Actions Secret 中，不放入代码、README 或聊天消息。

发布新版本时，先把代码提交到仓库，再创建对应标签和 Release。工作流必须包含在新版本标签所指的代码中。

## 手动补发

Actions → Publish Docker image → Run workflow，输入已有标签（如 `v0.3.4`）。默认只发布版本镜像；仅在需要把该版本设为当前最新版时勾选 `update_latest`。可用于补发或修复失败的发布。

自动发布是否成功，请查看 Actions 运行结果。现有服务器不会因此自动升级；服务器需主动拉取新镜像并重新创建容器，同时保留原数据卷。

## GHCR

工作流通过 GitHub 自动提供的 `GITHUB_TOKEN` 和 `packages: write` 权限发布，无需额外个人令牌。首次发布后在 GitHub 账号的 Packages → m3u-studio → Package settings 中确认可见性为 Public，使用户无需登录即可拉取。

```sh
docker pull ghcr.io/cachemiao/m3u-studio:latest
```
